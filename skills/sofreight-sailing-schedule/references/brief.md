# 船期对话交付

遵守仓库级 [docs/sof-specs/delivery.md](../../../docs/sof-specs/delivery.md)。  
本包打开「留源 + 清洗 + Excel」。接口返回多少条方案就汇总多少条。产品题见 [product.md](../../../docs/sof-specs/product.md)。

> **给用户看什么？** 一律用成功 JSON 里的 `view`（统一对话视图，脚本生成），
> 规则与话术见 [display.md](display.md)。**禁止**把下面的清洗列自行排成表贴进对话。
> `direct` / `transfer` 只供二次筛选或加工；Excel 用缓存源投影。

## 本包要解决什么

货代用起运港、目的港问有哪些班期（直航与中转）。成功：首轮给统一 `view`，港名多码时先让用户点名，禁止猜码。v1 不做订阅、推送、订舱。**货踪、塞港、运价、询盘不在本包查**，只给相关技能链接。

## 接口编排

A004 按港名/五字码解析港口 → 多条则停（`needs_port`）→ 用户给五字码 → A007 查船期（`confirm=0`）。书面约定当前查询不扣次数/浪花，故不做 A001 预检、查询侧不要求 `--confirmed`。未选定港口前不调 A007。一批里一港解析失败则该侧失败。

## 交互路径

- 「A 港到 B 港船期」：可能先选港，再查班期。
- 「刚才那次怎么解读 / 只要某船司」：读缓存；要最新或已过查询当日，先问是否重查。
- 确认：查询本身不扣费，「查一下」在港口已选定后可直接查。导出须明确同意。看合作商家：报完可加一句能力露出，不要追问；`--confirmed` 不算同意。用户已明确要找人则直接 `--partners-confirmed`。

## 推荐拍档

|---|---|---|
| 主查询成功后荐合作商家（A006 免费，3 家；禁止每次查询后追问） | 是 | 海运默认开。对外说「合作商家」（货代、拖车、清关、电商），不要说「拍档」。报完可加一句能力露出。仅用户露出需求或说要才 `--partners-confirmed`；意图明确不必再问。用户点名地点/公司才 `--keywords`。给人介绍 + 官网 `detailId` 链接 |

## 交付三问

| 问 | 本包 | 说明 |
|---|---|---|
| 留源 | 是 | 成功查询把 A007 的 `data` 写入 `~/.sofreight/exports/sailing-schedule-last.json` 的 `source`，并记 `queried_at`。用户二次问、要 AI 加工已查数据时只读缓存，禁止再打 A007。班期会变：必须交代查询时刻；用户要最新、或已过查询当日，先问是否重新查。禁止把缓存说成当前班期 |
| 清洗 | 是 | stdout 带清洗列（每类最多 30 条）+ `view`。不要把原始 `directList` / `transferList` 大 JSON 贴进对话 |
| Excel | 是 | 用户同意后从缓存 **源** 投影明细表。`--export-only` 不二次打接口 |

## 双轨说明（必读）

| 通道 | 内容 | 用途 |
|---|---|---|
| `view` | 脚本用**全量**清洗结果聚合成概览（直航约最多 12 条航线 + 中转精简表） | **首轮对用户展示**，原样照抄 |
| `direct` / `transfer` | 清洗行，**每类最多 30 条**；`direct_count` / `transfer_count` 仍是全量 | 二次筛选字段；**不是**完整清单 |
| 缓存文件 | 含 `source` 与全量清洗投影所需数据 | 二次问细节、导出 Excel；stdout 已去掉 `_full_*` / `source` |

二次问若要「全量明细 / 按船司筛完整班次」：读缓存或让用户导出，**不要**假定 stdout 里的 `direct`/`transfer` 已是全量。

## 聊天清洗列（字段字典，非展示模板）

### 直航（`direct` 数组，每条一班）

共舱组、船司、航线代码、运输类型（直航）、挂靠码头、目的港码头、周几、航程、空班标记、船名、航次、预计开船时间、预计到达时间、实际开船时间；码头计划（码头、开港时间、截港时间、港口中文名、港口英文名）。

同一共舱方案若有多条 `scheduleList`，**每条船期各出一行**。

首轮 IM：`direct` / `transfer` **每类最多 30 条**。超限时带 `chat_hint`；完整结果在缓存，可导出 Excel。

### 中转（`transfer` 数组，每个方案一行）

船司、航线代码、运输类型（中转）、中转港、挂靠码头、周几、航程、空班标记、一程船名、一程航次、一程ETD、一程ETA、二程船名、二程航次、二程ETD、二程ETA。

## 计费说明

当前船期查询**不扣次数/浪花**，不做额度预检，也不因额度不足拦截。仍须有效 API Key。A006 免费，不要提浪花。

## Excel（仅用户同意后）

从源投影两张表（字段与清洗列一致；直航把码头计划摊平为列）：

- **直航**：共舱组、船司、航线代码、运输类型、挂靠码头、目的港码头、周几、航程、空班标记、船名、航次、预计开船时间、预计到达时间、实际开船时间、码头、开港时间、截港时间、港口中文名、港口英文名
- **中转**：与聊天中转列相同

默认不落 xlsx。用户同意后 `--export`（随本次查询）或 `--export-only`（只读缓存）。Agent 只报 `export_path`，不要把表格读回对话。

若查询已成功但缺 `openpyxl`：`status` 仍为 `ok`，保留 `view`，另带 `export_error`（安装指引）；不要当成查询失败。

## 空结果怎么说

当前港口组合无直航也无中转：业务成功，说明「当前组合暂无船期，请更换查询条件」，不要换参狂重试。

## stdout

成功：`view`（必展）；`direct` / `transfer`（每类最多 30 条）、`direct_count` / `transfer_count`（全量）、超限时 `chat_hint`；`source_cached=true`，`queried_at`，`export_available=true`，`export_hint`。stdout 不含原始 `source` 与 `_full_*`。未同意时无 `export_path`。带 `--export` 且缺包时另有 `export_error`。**不要**在成功后改成 `needs_partners`。

**`view`**：脚本生成的对话 markdown（直航共舱概览 + 中转精简表 + 尾注）。**Agent 原样展示，禁止自行重排 / 另起炉灶 / 贴大 JSON**。细则见 [display.md](display.md)。

| 状态 | 对用户 |
|---|---|
| `needs_port` | 展示 `candidates_view`（或候选列表），等选择 |
| `missing_key` | 引导开通并配置 Key |
| `ok` | 原样给 `view`；可提醒导出；若有 `export_error` 说明导出环境问题，查询结果仍有效。可加一句合作商家能力露出，不要追问 |
