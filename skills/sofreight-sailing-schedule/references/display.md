# 统一对话展示规范（chat_view / view）

> 让**所有**使用本 skill 的 Agent / IM / 前端看到同一种船期数据形态：
> 直观、信息密度高、不拥挤、不错乱。本文件是展示的**唯一事实来源**。

## 核心原则

1. **脚本产文，调用方照抄。** 成功查询的 JSON 带 `view` 字段——一段已排版好的
   markdown 文本，由 `schedule.py::build_chat_view()` 生成。Agent 应**原样展示 `view`**，
   禁止自行重排、改写、精简后另起表格，也禁止把原始大 JSON 贴进对话。
2. **结构化数据仍在，但是截断的。** `direct` / `transfer`（各 ≤30 清洗行）与
   `direct_count` / `transfer_count`（全量）保留在 JSON 里，供 Agent 做**有限**二次筛选。
   这不替代 `view` 的展示地位。要全量明细 → 读缓存或导出 Excel（stdout 已去掉 `_full_*`）。
3. **补充说明放后面。** 如需额外提示（如筛选建议），以短句追加在 `view` 之后，
   不改动 `view` 内部。

## view 结构（自上而下）

```
**起运港（五字码）→ 目的港（五字码） 船期**
直航 N 条 · 中转 M 条〔，日期未标年份均为 YYYY 年〕（查询于 MM/DD）

**直航 · 航线概览**（按共舱航线合并，同船班次去重；另可导出全量明细）
| 承运船司（航线代码） | 挂靠码头 | 航程 | 空班 | 近 3 班（开船日 · 船名） |
|---|---|---|---|---|
> 空班＝已宣布停开的班期。
… 每条共舱航线一行 …

〔> 另有 K 条航线未展开，如需全量请筛选或导出。〕
〔> 目的港码头：…〕

**中转方案〔（前 30/38 条）〕**
| 船司 | 航线代码 | 中转港 | 航程 | 开船 ETD | 到港 ETA | 船名 · 航次 |
|---|---|---|---|---|---|---|
… 每方案一行 …

〔> 完整班次明细未在对话中平铺（避免拥挤）：可按 船司 / 开航日期段 / 船名·航次 再筛，
   或直接说「导出」拿 Excel 全量明细（含共舱、码头计划等所有字段）。〕
```

### 设计规则（为什么这样排）

| 问题 | 规则 |
|---|---|
| 直航动辄几百上千班 | 不平铺 30 行班次，按**共舱航线**聚合成概览，每条航线一行 |
| 共舱伙伴把同一班次重复 N 次 | 物理班次按（船名+航次+开船日）去重——三者皆同才合并；同船同日不同航次各自保留。共舱伙伴若航次写法不同，可能各留一条（可接受；避免真两航次被吞） |
| 空班混在班次里造成"有一行没船" | 空班剥离为服务级「空班」列（按日期去重），不再占班次行 |
| 接口错乱行（航程 0 天、空壳组） | 0 天不入航程列；无班次无空班的组直接跳过，不让脏行出现 |
| 一航线多家船司多套服务代号 | 船司并排展示（超 3 家折叠为「等 N 家」）；航线代码仅整组唯一时展示 |
| 日期带时分太长 | `2026-09-11 20:00` → `9/11 20:00`；整点或午夜省略时分；跨年才带年份 |
| 表格过宽错乱 | 直航 5 列、中转 7 列，列内用「；/、」紧凑分隔 |

| 有钟点/无钟点混排说明

开船时刻（ETD）带非 00:00 时分时保留，如 `9/14 11:00`——它是有价值的截关参考；
无时分只给 `9/14`。同一列两种形态并存是预期行为，不要"统一"抹掉时刻。

### 近 3 班的取舍

- 只展示该航线**未来最近 3 班**（按 ETD 升序取 >= 今天）。
- 若未来不足 3 班，用最近的**已开历史班**补足并逐个标注「（已开）」，
  避免用户误订已开船的舱位。

## Agent 交付话术（统一）

| 状态 | 标准话术 |
|---|---|
| `ok`（有结果） | 原样给 `view`；其后可补一句 `需要完整班次/按船司或日期筛选，或导出 Excel，告诉我即可。` |
| `ok` 但直/中转 0 | `**{路线} 船期**：当前组合暂无船期，请更换查询条件。`（`view` 已含此句） |
| `ok` + `export_error` | 仍展 `view`；另说明导出失败原因（通常缺 openpyxl），**不要**当成查询失败 |
| `needs_port` | 展示 `candidates_view`（或候选表：`五字码｜中文名｜英文名`），问用户选哪个；选定后带 `--pol-code/--dest-code` 重查。禁止猜码 |
| `missing_key` | 按 `references/auth.md` 引导注册开通并配置 Key，不回显 Key |
| `failed` | 照抄 `error`，不再换参狂重试 |

### 追问与二次加工

- 「有哪些船司/近期班次」→ 回答基于 `view` 概览即可。
- 「某船司 / 某日期段 / 某船名（航次）」→ stdout 里 `direct`/`transfer` **可能已被截断到 30 条**，
  不够时读缓存全量或带参重查（`--carrier`、`--etd-start/--etd-end`、`--vessel`、`--voyage`；
  注意接口为完整匹配，船名/航次需给全名，不做模糊查询）。
  过滤结果建议仍以「直航概览 + 精简班次」同构呈现，保持风格一致。
- 「导出」→ 用户同意后 `--export`（随查询）或 `--export-only`（读缓存）。
  只报 `export_path`；若有 `export_error` 说明环境缺包，查询结果仍有效。不要把表读回对话。

## 实现备注

- `view` 由脚本生成（`build_chat_view`），本文档若与实现冲突，以代码为准并向作者反馈。
- 聊天上限仍是每类 30 条清洗行（`direct`/`transfer`）；`view` 用全量 `_full_*` 聚合后再丢掉 `_full_*`，
  概览不受 30 条上限约束（约 12 条航线即可覆盖多数场景）。二次问全量请读缓存或导出。
